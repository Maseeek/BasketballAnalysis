# Basketball Analytics Engine

This project is a computer vision and backend API system designed to analyze basketball shots in video footage. It tracks the ball's trajectory, detects field goal attempts (FGA) and makes (FGM), calculates shooting percentages, and measures the release angle of the shot.

## Project Structure & Files

### 🧠 Core Logic
*   **`cv_core.py`**
    *   **The heart of the application.** Contains the `BasketballTracker` class.
    *   This file holds all the complex OpenCV math, physics logic, and state management required to find the ball, detect a shot attempt, figure out if it went in the hoop, and calculate the release angle.
    *   *Note: This file does not draw any UI or run a server; it purely processes frames and returns data dictionaries. It is imported by other scripts.*

### 🌐 Backend Server (For Web Apps)
*   **`server.py`**
    *   A Flask API designed to serve a web frontend (e.g., `nothingbutnet.online`).
    *   It exposes an `/upload-and-analyze` endpoint where a website can `POST` a video file along with hoop coordinates.
    *   It uses `cv_core.py` to quietly analyze the video in the background and returns a clean JSON summary (makes, misses, streaks, angles) for the frontend to display.

### 🖥️ Local Testing & Debugging (For Developers)
*   **`visual_debug.py`**
    *   A desktop GUI tool to test the detection algorithm locally.
    *   When you run it, you choose a video, click the hoop corners, and an advanced "BASKETBALL ANALYSIS" dashboard appears showing real-time stats alongside the video feed.
    *   *This replaced the old `main.py` file, serving as the primary visual way to verify the math in `cv_core.py` looks right to human eyes.*
*   **`test_bench.py`**
    *   An automated accuracy testing script.
    *   Run `python test_bench.py --setup` to map hoop coordinates and ground truth (Make/Miss) sequences for videos in the `Resources/Videos` folder.
    *   Run `python test_bench.py --test` to have the computer vision engine process all mapped videos and output an accuracy report card comparing what it predicted vs. the ground truth.
*   **`ground_truth.json`**
    *   A data file generated by `test_bench.py` that stores the human-verified correct answers for the test videos.

### 🤖 Automated Server Verifiers
*   **`verify_server.py`**
    *   A quick health-check script to ensure `server.py` is capable of starting up, accepting mock initialization data, and resetting correctly.
*   **`verify_video_upload.py`**
    *   An end-to-end integration test. It boots up `server.py` and actively sends a test video (`NEAVid2.mp4`) via a POST request to verify the entire upload, processing, and JSON response lifecycle works perfectly.

## Quick Start
*   **To see the algorithm working locally:** `python visual_debug.py`
*   **To run the production backend:** `python server.py`
*   **To test algorithm accuracy:** `python test_bench.py --test`
